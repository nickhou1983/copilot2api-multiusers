Before You Start — 全局使用注意事项（1 of 4）

上线前先把身份、命名与请求画像管住

Copilot2API 能把客户端协议统一起来，但账户身份、命名方式和上游请求头画像仍由运营方负责。建议把下面三项作为部署基线，而不是发生封禁、模型缺失或兼容错误后再补救。

Guardrail 01 · Account Naming

账户名不要模式化

避免使用“固定前缀＋连续编号”的批量命名，也不要把基础设施角色直接写进名称。

  • 不建议：gateway-01、route-02、proxy-03
  • 采用自然、稳定、可审计的账户名称
  • 账户与路由关系保存在管理配置中，不编码进名称
Guardrail 02 · Header Lifecycle

请求头要定期更新

上游会根据客户端版本与集成身份决定模型可见性和行为；长期冻结请求头会逐渐偏离真实客户端。

  • 跟踪 OpenCode 与 VS Code Copilot Chat 的源代码/版本变化
  • 版本化维护 User-Agent、Editor/Plugin Version、Intent 等 profile
  • 每次升级先跑模型列表与真实调用回归
Guardrail 03 · Auth Method

身份验证方式建议采用 OpenCode 方式

建议优先采用 OpenCode 的 OAuth Device Flow：使用 OpenCode Client-ID 获取 GitHub OAuth token，并直接作为 Copilot API Bearer，减少短时 Copilot token 的交换与刷新环节。

  • OpenCode Client-ID → GitHub OAuth token
  • GitHub OAuth token → Copilot Bearer（无需二次交换）
  • Client-ID、token 用法与 ProfileOpenCode 必须成套匹配
Operational Rule
不要通过伪造任意客户端画像来“试出”能力；以真实开源客户端当前实现为基线，记录版本并定期复验。

Before You Start — 全局使用注意事项（4 of 4）

代理侧用白名单；Copilot 网关却是黑名单

GitHub Copilot 不会完整校验每个 anthropic-beta token：未知甚至伪造的 token 往往仍返回 200，但这不代表功能生效；命中其明确黑名单时，整个请求会直接 400。因此代理出站必须采用最小白名单。

建议的基线白名单 · 只按真实载荷注入
interleaved-thinking-2025-05-14Native Messages 基线；由代理统一生成，不接受客户端任意透传。
context-management-2025-06-27仅当 body 含 context_management 时注入。
compact-2026-01-12仅在 compaction / compact 相关请求中注入。
  • 基线字段参考 OpenCode / VS Code 当前实际发送值，并随客户端版本更新。
  • 客户端提供的其他 beta 默认剥离，避免一个危险 token 打死整次请求。
Copilot 明确拒绝的 5 个 token · 400
files-api-2025-04-14
mcp-client-2025-11-20
skills-2025-10-02
advisor-tool-2026-03-01
output-128k-2025-02-19
  • 200 只表示网关接受：伪造 token、output-300k 等都可能被静默忽略。
  • 400 表示硬拒绝：黑名单 token 会让整个请求失败，不能依赖上游自动忽略。
  • 策略：客户端 beta → 代理解析 → 按功能白名单重建出站头，而不是原样转发。
Decision Rule
接受 ≠ 生效。判断 beta 功能必须做三探针：仅带头、带头＋真实载荷、同载荷不带头；只有负向对照失败才证明该头确实必需。

Before You Start — 场景化接入注意事项

开发者隔离身份；应用侧保持 Session 粘性

开发者工具和后端应用的风险模型不同：前者重点是个人身份隔离与隐私边界，后者重点是账户池负载、会话连续性和故障转移。不要用同一套轮询规则覆盖两种场景。

Developer Scenario · Claude Code / OpenCode

一人 · 一 Key · 一 GitHub 账户

  • 每位开发者使用独立 Copilot2API Key，并固定映射到唯一 GitHub 账户。
  • 禁止多人共享 Key / 账户；确保用量归属、撤销、限额和审计都能落到个人。
  • 优先评估 OpenCode：实现可审计，Direct 模式也以其请求头 profile 为参考。
  • Claude Code 可能携带客户端环境或遥测相关信息；接入前核对配置、数据政策与组织隐私要求。
Application Scenario · Account Pool

按 Session 负载，而非逐请求乱跳

  • 建立稳定的 Session → GitHub 账户映射，同一会话优先保持账户粘性。
  • 综合账户健康、并发、限额和缓存状态分配新 Session，避免简单无状态轮询。
  • 故障转移尽量发生在请求/轮次边界，并记录切换原因；避免破坏上下文、缓存与工具连续性。
  • 监控每账户成功率、429/5xx、token 用量与活跃 Session，及时隔离异常账户。

Issue 01 — 上游模型硬性不支持的功能

现象与判定：不是代理丢功能，是上游不放行

早期怀疑「代理把功能弄丢了」。用三层对照法(① Anthropic 官方文档 → ② 直连上游 → ③ 经代理)复测后判定:以下能力在 Copilot 当前暴露的同步接口上被拒,换 beta 头 / 工具版本也打不通(fast mode 例外 —— 07-26 复测已翻转为支持):

能力实测上游报错 / 结论
web_search(任何版本 / beta 组合) ✕ 400 The use of the web search tool is not supported.
web_fetch(工具与 beta 头双白名单均堵) ✕ 400 rejected tool(s): web_fetch / unsupported beta header(s)
外链图片 / PDF
source.type=url		 ✕ 400 external image / document URLs are not supported —— 两者仅接受 base64
300K 扩展输出
官方仅 Message Batches API		 △ 当前路径不可用 同步 /v1/messages 仍为 128K；直连 Copilot 边界实测 128000 ✓ / 128001 ✕，详见 Extended 专页
fast mode 真实加速
07-26 复测状态翻转		 ✓ 已支持 专属 ID claude-opus-4.8-fast 生效:回报 usage.speed:"fast",实测 2.46×(54.3→133.4 tok/s);官方 speed 参数 + beta 头仍被静默忽略
